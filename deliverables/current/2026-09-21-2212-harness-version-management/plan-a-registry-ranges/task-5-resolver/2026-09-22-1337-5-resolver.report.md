## The rulings/deviations applied, and where

1. `== null` guard + `string | null` param in `resolveVersion` (`src/registry/resolve.ts`, first guard inside the function) — per the controller's ledgered pre-flight ruling. **Noted as required by the tasking.**
2. Wildcard fix in `parseVersion` (`src/registry/resolve.ts`) — required to satisfy the brief's own Step 1 test for `'3.x'`:

```ts
function parseVersion(raw: string): string | null {
  const cleaned = raw.trim();
  const exact = valid(cleaned);
  if (exact !== null) return exact;
  // A wildcard range like "3.x" or "1.2.x" is a range spec, not an installed
  // version — coerce would fabricate e.g. 3.0.0, so treat it as unparseable.
  if (/[xX*]/.test(cleaned)) return null;
  return coerce(cleaned)?.version ?? null;
}
```

   Evidence for the contradiction (checked directly against installed `semver`): `valid('3.x') → null`, `coerce('3.x') → 3.0.0` (also `coerce('1.2.x') → 1.2.0`, `coerce('*') → null`, `coerce('x') → null`). With the brief's one-liner, `'3.x'` parsed to `3.0.0` and hit the `≥0.155.0, max:null` unverified range. Real-world installed-version strings this must still handle are unaffected: `valid('v0.150.0') → 0.150.0`, `coerce('0.150') → 0.150.0`, plain `0.150.0` → exact.
