# Fix Report (post-review)

**Finding addressed:** (Important, plan-mandated, controller-ruled) `readSkillFrontmatter`
propagated `gray-matter` parse errors on malformed YAML frontmatter, which would crash the later
doctor/enable flows. Required behavior: degrade to `{ hasSkillMd: true, frontmatter: undefined }`
so the future skill-frontmatter rule can surface it as a finding.

## Changes

Only the two authorized edits — nothing else touched, no reformatting:

1. `src/canon.ts` — wrapped the `readFileSync` + `matter(raw)` calls inside
   `readSkillFrontmatter` in a `try/catch`. On any read/parse error it now returns
   `{ hasSkillMd: true, frontmatter: undefined }` with the controller-specified comment. Import
   list unchanged; `readFileSync` remains imported (still used inside the try block). All other
   functions in the file untouched.
2. `src/canon.test.ts` — appended one test after the existing five:
   `degrades to undefined frontmatter for malformed YAML instead of throwing`, written a SKILL.md
   with `name: [unclosed` YAML and asserting `hasSkillMd === true` and `frontmatter` undefined.
   Adapted the snippet's `root` to the file's existing temp-root variable `repoRoot`; no other
   test code changed.
