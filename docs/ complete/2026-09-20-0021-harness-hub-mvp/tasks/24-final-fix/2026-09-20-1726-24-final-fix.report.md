## Deviations

Rather than refactor `canon.ts` (out of scope for this round), `migrate.ts` gained a small private `readHarnessSkillFrontmatter(skillMdPath)` helper that mirrors canon's exact semantics (gray-matter parse; malformed YAML degrades to `frontmatter: undefined`, never throws; missing file → `hasSkillMd: false`). The validation call `validateSkillFrontmatter(e.name, frontmatter)` is exactly as specified in the brief. Rationale: minimal-diff constraint beats a wider refactor; behavior is identical to the canon reader.
2. **One canon-side assertion updated (within brief scope):** the `'copies a new skill into canon...'` test asserts the copied file content; since the fixture content changed per Step 1c, that one assertion string was updated to the same frontmatter-carrying content (still asserting a byte-identical copy). No assertion semantics changed.

Nothing else deviates: test bodies are verbatim from the brief (two transient typos introduced during editing — a mangled StrReplace block and `repoot` — were caught and corrected before any RED/GREEN run; final test code matches the brief).
