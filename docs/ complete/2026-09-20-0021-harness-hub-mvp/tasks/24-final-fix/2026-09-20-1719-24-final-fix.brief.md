## FIX 1: `migrate` must validate entries before adopting them into canon (spec §6)

**Spec §6 (binding):** "For each entry under `.claude/skills/<name>/`, first validate against the skill-shape and frontmatter contract (§7) — anything that fails is a clobber-risk error." ## FIX 2: `enable` on an already-enabled harness with drift must refresh the wiring (spec §8)

**Spec §8 (binding):** "re-running after canon changes refreshes the wiring." Today `src/commands/enable.ts` short-circuits already-enabled harnesses with zero work, so doctor's drift remediation ("Re-run harness-hub enable <id>") is a no-op. 

**Ruled fix:** in the already-enabled branch, before reporting `already-enabled`, check for `generated-file-drift` findings for that id in `allFindings`. If any exist AND the harness has no blocking errors, re-run `wireMigrateSymlinkHarness(repoRoot, entry)` (idempotent — it repairs missing/wrong links and leaves correct ones alone). Status stays `'already-enabled'`, blockingFindings stays `[]`, config untouched. The no-blocking-errors guard preserves foreign-file safety: a hand-written `CLAUDE.md` produces a `clobber-risk` ERROR (not drift), so without `--force` the foreign file is never clobbered; with `--force` the forceable clobber-risk is bypassed per the Resolved Ambiguities.
